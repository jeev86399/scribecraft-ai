# ScribeCraft AI V4 - GPU Training via Google Colab

Use this package to train the DistilBERT neural ensemble on a free T4 GPU in Google Colab. The CPU training takes significantly longer.

## Reproducibility Workflow

### A. Enable T4 GPU
1. Open Google Colab (colab.research.google.com) and create a new notebook.
2. In the top menu, go to **Runtime > Change runtime type**.
3. Select **T4 GPU** as the hardware accelerator and save.

### B. Upload ml-server-v4.zip
Upload the `ml-server-v4.zip` file (generated by `create_colab_package.sh`) into the Colab file explorer on the left.

### C. Verify CUDA
Run this cell in your notebook to ensure the GPU is attached:
```bash
!nvidia-smi
```

### D. Extract project
```bash
!unzip -q ml-server-v4.zip
```

### E. Install dependencies
```bash
!bash ml-server/colab/setup_colab.sh
```

### F. Verify dataset
Ensure the datasets were extracted properly:
```bash
!ls -la ml-server/datasets/v4/
```
You should see `v4_train.jsonl`, `v4_val.jsonl`, and `v4_test.jsonl`.

### G. Run training
Launch the GPU-accelerated training script. This automatically uses Automatic Mixed Precision (AMP) and Gradient Accumulation.
```bash
!python ml-server/colab/train_colab.py
```
*Note: The actual training time depends on Colab's current GPU allocation.*

### H. Locate best_model.pt
Once training is done, locate the checkpoint:
```bash
!ls -la ml-server/models/v4/best_model.pt
```

### I. Locate isotonic_calibrator.pkl
Locate the calibration file:
```bash
!ls -la ml-server/models/v4/isotonic_calibrator.pkl
```

### J. Download trained artifacts
Right-click on `best_model.pt` and `isotonic_calibrator.pkl` in the Colab file explorer and download them to your computer.

### K. Copy artifacts back to Mac
Place both downloaded files into your local ScribeCraft directory exactly here:
`ml-server/models/v4/best_model.pt`
`ml-server/models/v4/isotonic_calibrator.pkl`

### L. Run final benchmark
On your Mac, inside the `ml-server` directory (with your `venv311` activated), evaluate the trained checkpoint against the strictly held-out final test set:
```bash
python training/benchmark.py
```

### M. Start API
Start the local ML API server:
```bash
python main.py
```
Check that the weights loaded by visiting `http://127.0.0.1:5002/health`.

### N. Run unseen detector tests
Run your local test script to verify real-world predictions:
```bash
python test_detector.py
```

## Troubleshooting

- **Invalid ZIP**: If `unzip -q ml-server-v4.zip` fails, the upload was likely interrupted. Delete it from Colab and upload again.
- **CUDA unavailable**: If the training script crashes saying CUDA is unavailable, you forgot to set the Runtime to T4 GPU. Go to Runtime > Change runtime type.
- **Missing dataset**: If it says the dataset path is invalid, ensure you generated the dataset locally before running `create_colab_package.sh`.
- **Missing model**: If `best_model.pt` isn't found at the end, training likely crashed or was interrupted before the first epoch finished.
- **Out-of-memory**: If you get a CUDA Out of Memory (OOM) error, lower the `batch_size` in `configs/v4.yaml` and increase `gradient_accumulation_steps`.
- **Interrupted training**: If Colab disconnects, just re-run `!python ml-server/colab/train_colab.py`. It will detect `latest_checkpoint.pt` and resume automatically.
